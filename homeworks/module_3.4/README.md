# Non-Blocking Buzzer Audio Player for ESP32 (ESP-IDF)

**Неблокуючий аудіо-плеєр мелодій для пасивного зумера**, реалізований на базі фреймворку **ESP-IDF** у середовищі **PlatformIO**. 

Проект орієнтований на роботу з платами серії **ESP32-S3** (підтримує специфіку архітектури `LEDC` та джерел тактування для S3), але може бути легко адаптований під класичний ESP32.

## 🚀 Особливості реалізації
* **Апаратний ШІМ (LEDC):** Генерація звукових частот відбувається апаратно «на льоту» без навантаження на обчислювальні ядра.
* **Фіксований часовий тік (50 мс):** Керування тривалістю нот зав'язане на кванти часу через високорівневу систему таймерів `esp_timer`.
* **Повна неблокуючість:** Система **не використовує** створення важких FreeRTOS тасків для плеєра та повністю уникає блокуючих затримок типу `vTaskDelay()` або `delay()`.
* **Вільний `app_main`:** Головний цикл програми залишається на 100% вільним для виконання іншої критичної логіки (опитування датчиків, робота з Wi-Fi тощо).
* **Модульна C++ архітектура:** Словник нот, масиви мелодій та логіка периферії повністю розділені на незалежні класи та простори імен.

---

## 📂 Структура проекту

* **`include/Pitches.hpp`** — Словник частот нот від 1 до 6 октави (на основі стандартних музичних частот у Гц).
* **`include/Melodies.hpp`** — Плейліст з масивами мемних та класичних мелодій (Маріо, Сігма, GigaChad, Chipi Chipi, звуки).
* **`include/BuzzerPlayer.hpp`** — Оголошення C++ класу плеєра, констант та інтерфейсу керування.
* **`src/BuzzerPlayer.cpp`** — Реалізація ініціалізації LEDC, прив'язки таймерів та неблокуючої обробки тіків (`on_tick`).
* **`src/main.cpp`** — Точка входу `app_main`, демонстрація послідовного відтворення черги треків з плейліста.
* **`result/`** — Папка з матеріалами демонстрації фінальної збірки пристрою та результатами тестування.

## 🔌 Схема підключення (Hardware)

Для реалізації проекту необхідна плата **ESP32-S3** та **пасивний зумер (Passive Buzzer)**.

> ⚠️ *Важливо:* Активний зумер (з вбудованим генератором) не підійде, оскільки він не вміє змінювати тональність залежно від частоти ШІМ.

```text
       ESP32-S3 DevKit                      Пасивний Зумер
    ┌──────────────────┐                ┌──────────────────┐
    │                  │   100-220 Ohm  │                  │
    │      GPIO 4 ─────┼─────[████]─────┼───► (+) Signal   │
    │                  │                │                  │
    │       GND  ──────┼────────────────┼───► (-) GND      │
    │                  │                │                  │
    └──────────────────┘                └──────────────────┘
```
*Резистор на 100–220 Ом є опціональним, але рекомендованим для обмеження вихідного струму з GPIO піна мікроконтролера.*

## 🛠️ Налаштування середовища (`platformio.ini`)

Приклад базової конфігурації для збірки проекту під ESP32-S3 з використанням чистих бібліотек фреймворку ESP-IDF:

```ini
[env:esp32-s3-devkitc-1]
platform = espressif32
board = esp32-s3-devkitc-1
framework = espidf
monitor_speed = 115200
```

## 🎵 Як розширити список мелодій?

Щоб додати новий трек, не потрібно змінювати код плеєра. Достатньо відкрити `include/Melodies.hpp` та описати нову структуру всередині `namespace Melodies`:

```cpp
inline const Note my_new_melody[] = {
    {NOTE_C4, 4},  // Грати До 4 октави протягом 4 тіків (4 * 50мс = 200мс)
    {NOTE_PAUSE, 2}, // Пауза на 2 тіки (100мс)
    {NOTE_E4, 4},  // Грати Мі 4 октави
    {0, 0}         // Обов'язковий маркер кінця мелодії
};
```
Після цього додайте вказівник на масив у `playlist[]` всередині файлу `src/main.cpp`.

## 📺 Демонстрація роботи (Result)

У папці **`result/`** ви знайдете відеозапис, який наочно демонструє роботу цього проекту. На відео зафіксовано:
1. Послідовне та повністю неблокуюче відтворення всього циклу мелодій.
2. Логи в моніторі порту (Serial Monitor), які виводяться паралельно зі звуком без жодних затримок.
3. Чітку та чисту роботу пасивного зумера на апаратних частотах мікроконтролера ESP32-S3.
