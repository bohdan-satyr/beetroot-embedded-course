# Модуль 2.1. Домашнє завдання: Embedded C++ на ESP32

Цей проєкт демонструє перехід від класичного стилю програмування Arduino (з використанням блокуючих функцій та глобальних змінних) до сучасних практик **Embedded C++** для мікроконтролера ESP32. 

Мета роботи — рефакторинг базового прикладу Blink за канонами ООП, оптимізація пам'яті, побудова неблокуючої архітектури та безпечна робота з периферією.

## 📁 Структура проєкту

Репозиторій має чітку модульну структуру, орієнтовану на PlatformIO:

* **`src/`** — основний робочий простір програми:
  * `main.cpp` — реалізація неблокуючої архітектури Superloop, скінченного автомату режимів роботи, обробка переривання кнопки (ISR) та вимірювання швидкості циклу.
  * `Config.h` — єдине джерело конфігурації. Вкладені структури (`Led`, `Button`, `Monitor`) використовують `constexpr` для повного усунення "магічних чисел".
* **`lib/Led/`** — ізольований компонент для роботи з індикацією:
  * `Led.h` — оголошення класу `Led` з `const` методами та безпечного переліку станів `enum class LedState : uint8_t`.
  * `Led.cpp` — реалізація методів ініціалізації `init()` та комутації станів `set()`.
* **`classic_Blink_Arduino_example/`** — оригінальний "класичний" Arduino Blink, який брався за основу для порівняння та рефакторингу.
* **`result/`** — підтвердження успішного виконання завдання:
  * `info_from_SerialMonitor.txt` — лог виводу метрик швидкості виконання циклу `loop()` та зміни режимів.
  * Відеодемонстрація — запис роботи зібраної схеми на макетній платі (breadboard).
* **`platformio.ini`** — файл конфігурації середовища PlatformIO.

## 🛠 Реалізовані концепції та технічні деталі

1. **Об'єктно-орієнтований підхід (ООП):**
   * Робота з LED інкапсульована в клас `Led`. Конструктор позначено як `explicit` для запобігання неявних перетворень типів.
   * Стани світлодіода (`LedState::ON` / `OFF`) та режими роботи системи (`LedMode`) захищені через `enum class`.

2. **Оптимізація пам'яті та безпека типу констант:**
   * Повна відмова від важких контейнерів STL та динамічного виділення пам'яті (Heap).
   * Номери GPIO та інтервали визначені через `static constexpr` у `Config.h`.

3. **Неблокуючий Superloop та Скінченний автомат:**
   * Проєкт працює без жодного виклику `delay()`. Усі затримки (блимання, антидребезг) розраховуються через `millis()`.
   * Перемикання станів LED реалізовано за допомогою оператора `switch-case` на основі поточного режиму роботи.

4. **Асинхронна обробка кнопки (Interrupts & Debouncing):**
   * Натискання кнопки зчитується асинхронно через апаратне переривання (`attachInterrupt`).
   * Обробник переривання `handleButtonInterrupt()` є ультра-мінімальним (розміщений в `IRAM_ATTR`, лише піднімає `volatile bool` прапорець `buttonPressed`).
   * Програмний антидребезг (debouncing) з інтервалом **50 мс** та вся логіка циклічного перемикання режимів (*Блимання → Постійно увімкнено → Постійно вимкнено*) безпечно обробляються в `loop()`.

5. **Телеметрія та вимірювання швидкості програми:**
   * Кожні 1000 ітерацій циклу `loop()` програма обчислює точний середній час виконання однієї ітерації за допомогою `micros()`.
   * Результати виводяться в Serial Monitor (швидкість порту — **115200 baud**).
